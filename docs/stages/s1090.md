# s1090 — TRD-16 engine loop, snapshots, problems and events

Summary: trd-core's engine runs start-up and the tick (guard, config reload, scan, EXIF, queue, promotion) and publishes a revision-stamped §6.10 snapshot whenever its content changes, with controls applied through one async handle.

What changed:
- `engine.rs`: `Engine` owns the store, config, tools, scanner, render queue, histograms, problems and snapshot. `Engine::new` returns the engine and an `EngineHandle` (controls over an mpsc channel, the snapshot on a `watch` channel). `startup`, `tick`, `apply` and `run` are callable directly, so tests drive it without the run loop.
- `snapshot.rs`: the §7 types in plain Rust (`Snapshot`, `SequenceCard`, `VariantRow`, `RenderedVideo`, `FailureCard`, `Counts`), the §6.10 `in_progress` order, the stage and phase rules, the count-mismatch note, and the 60 s `file_exists` cache.
- `problems.rs`: the problem set keyed by stable id (`fda`, `tool:<name>`, `config`, `config-issues`, `codec:<name>`, `path:<path>`), keeping `since_ms` while a problem persists and sorting errors first.
- `events.rs`: `EVENT_CONFIG_RELOADED`; the six TRD-12 names are unchanged.
- `controls.rs`: `pause_all_rendering` now skips adopted foreign renders (one guard, outside the listed files; see the decision record).
- `tests/engine.rs`: the ten named tests (`lifecycle`, `ordering`, `fda_blocks_scanning`, `config_reload_event`, `phases`, `problems_lifecycle`, `snapshot_counters`, `count_mismatch`, `file_exists_cache`, `foreign_render_left_alone`). They use the fake ffmpeg and a `/bin/sh` EXIF stand-in in temporary directories, with manual clocks and a fake process table.

Decisions:
- The revision goes up by exactly one per published change of content, and a tick or control that changes nothing keeps it. `generated_at_ms` and the revision are not part of the comparison.
- The phase precedence is the §6.10 list: starting, no config, waiting for disk access, paused, rendering, exporting, idle. Starting holds until the first tick has run.
- While Full Disk Access is missing, the engine clears the scan (nothing is listed), reaps running renders and promotes nothing.
- A sequence with more exported frames than its raw sequence is kept out of the queue, so it never renders; it is listed as `STAGE_COUNT_MISMATCH` with the §6.10 note.

Verification: `cargo test -p trd-core` passes (all test binaries, including the ten engine tests); `cargo clippy --all-targets -D warnings`, `cargo fmt --check`, `check-spdx.sh` and `check-test-names.py --ticket TRD-16` pass.
