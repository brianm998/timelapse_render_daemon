# Stage s1091: bounded tool pipe joins and a 20-minute Windows v3-gate limit (TASK-1112)

Summary: The tool pipe joins in `trd-core` are bounded per chunk by the pipe grace, returning the bytes received so far, and the Windows `trd` job of v3-gate has a 20-minute limit so a future hang costs minutes instead of 6 h.

## Findings

- The Windows hang was in `tests/scan.rs` (`slow_path_does_not_block`), seen in the develop push run 45499652348 (job 138819226979), which passed `tests/process.rs` (6 tests) and `tests/plan.rs` (36 tests) before stopping at "has been running for over 60 seconds" until GitHub cancelled it at 6 h.
- #1104 (TRD-06b) fixed it and merged as fa1bd9de6, making the scan tests hang-proof on Windows (8221194, 32a2983, 25412ee, 3489f14). `tests/scan.rs` is owned by #1104 and is not touched here.
- Since then `trd (windows-2022)` is green, with the step taking about 2 min: develop push run 45552022957 and batch b745-2 run 45578308426.
- The 6 h cost came from the Windows job having no `timeout-minutes`, so it used GitHub's 6 h default.

## What this stage adds

- `.github/workflows/v3-gate.yml`: the `trd` job has `timeout-minutes: ${{ matrix.os == 'windows-2022' && 20 || 360 }}`. Linux and macOS keep 360. The owner approved this workflow edit on 2026-11-25.
- `tools.rs` `join_pipe`: the `PIPE_GRACE` deadline is checked on every chunk, so queued chunks cannot extend the wait past the grace. When the grace expires, the bytes received so far are returned and later grandchild output is dropped. This is a behaviour change: before, queued chunks could keep the join going past the grace.
- Tests: the hang-guarded probe test (a grandchild holding the pipe longer than the guard) stays, and `bounded_run_returns_partial_bytes_when_the_grace_expires` pins the partial-bytes return. Both are `#[cfg(unix)]` because they run `/bin/sh` and a `sleep` grandchild; the rest of the probe path is covered on every platform.
