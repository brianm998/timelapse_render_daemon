# s1013 — TRD-07 render planning: names, frame patterns, aspect, ffmpeg argv

Summary: trd-core plans a render from a complete image sequence and a variant: it detects the frame pattern, probes the source size when needed, names the output, reports already-rendered outputs and builds the exact ffmpeg argv of §6.5 (`Plan::argv`).

What changed:
- `pattern.rs`: `decompose` and `detect` ported from the Swift code, with the 5-frame demuxer probe range as `IMAGE_DEMUXER_PROBE_RANGE`.
- `aspect.rs`: `aspect_string` ported from `AspectRatio.string`.
- `plan.rs`: `output_filename` (delegates to `Config::output_filename`), `already_rendered`, `probe_size` (ffprobe through `Tools`), `final_size`, the serialisable `Plan` with `argv`, `plan_render` (`PlanRequest` in, `PlanError` out), and a local `JobStatus` with the `render_jobs` labels for TRD-12.
- `tests/plan.rs`: the ported Swift tests and the named A1–A7 tests. The size probe tests use a `/bin/sh -c` stand-in ffprobe, so they need no built fake binaries and `trd-testtools` is not a dependency of `trd-core`.

Decisions:
- Original-size and width-only renders always probe the first frame; a probe failure is `NotQueueable`.
- The `no_pattern` error carries the summary only; its detail is empty until TRD-11's `analyze_input_sequence` supplies the input analysis.
- `PlanError::UnknownCodec` is returned as an error; its failure kind is `FAILURE_NOT_QUEUEABLE` as well.
- The ffprobe call is bounded by `PROBE_TIMEOUT` (30 s) through `tools::run_bounded`, which kills it on timeout.
