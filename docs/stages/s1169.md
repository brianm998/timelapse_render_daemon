# Stage s1169: the trd Windows job is green again (batch #785)

Summary: The `trd` CLI usage-error test expects the usage name with the platform's executable suffix (`trd.exe` on Windows), so the windows-2022 job of batch #785 passes again.

## Findings

- Batch #785 was red in `trd (windows-2022)` on the base alone. The failing assertion is
  `service_without_an_action_is_a_usage_error` in `crates/trd/tests/cli.rs`.
- clap builds the usage name from argv[0]'s file name, which is `trd.exe` on Windows, so stderr
  reads `Usage: trd.exe service <COMMAND>` and the old `Usage: trd service` check failed.

## What this stage changes

- `crates/trd/tests/cli.rs`: the expected text is `format!("Usage: trd{} service", std::env::consts::EXE_SUFFIX)`.
  The exit-code-2 assertion and the other tests are unchanged. No product code changes.
- `docs/decisions/1159-cli-usage-name-on-windows.md` records the decision.
- `scripts/exit/s1169.sh` runs the trd CI script and the `cli` test target.
