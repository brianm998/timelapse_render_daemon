# s1125 — TRD-21 service install, uninstall, status, restart

Summary: `trd service install|uninstall|status|restart` sets up and controls the per-user autostart on macOS (LaunchAgent), Linux (systemd user unit) and Windows (logon task) as spec 1 §10.4 says, with the three templates as packaging files and a live system test.

What changed:
- `packaging/macos/com.timelapserender.trd.plist`, `packaging/linux/trd.service`, `packaging/windows/task.xml.in`: the §10.1–10.3 templates, embedded by the binary with `include_str!`. Values are XML- or systemd-escaped when rendered.
- `src/service/mod.rs`: `Target` (home, uid, user, binary, config, the package copies, dry-run flag and a `CommandRunner`), the `CommandRunner` trait, `SystemRunner` (refuses under `cfg(test)`), `RecordingRunner`, the `Service` trait, `run`, and the single-pass template filler.
- `src/service/macos.rs`, `linux.rs`, `windows.rs`: one `Service` implementation per OS with its unit tests. Goldens are `tests/golden/service/*`.
- `src/cli.rs` routes `trd service …` to the service module; `trdw.rs` includes the module too, since it compiles `cli.rs` by path.
- `Cargo.toml`: `libc` moves to a unix normal dependency (the uid). `Cargo.lock` is unchanged.
- `tests/service_live.rs`: the `TRD_SERVICE_TEST` system test. It installs, waits for `status: running` and a loopback `GetServerInfo`, restarts (new pid, or new last run time on Windows), uninstalls, and waits for the port to stop answering.

Decisions: see `docs/decisions/1114-service-install-decisions.md`.

Acceptance A1, reconciled with decision 1114: the package copy short-circuits install only where §10.4 says. On macOS, when the `/Library` agent exists, install does nothing. On Linux, when the package unit exists, install skips only the per-user unit write; it still runs `systemctl --user daemon-reload` and `enable --now trd`. Windows has no package copy. The tests `install_writes_no_unit_when_the_package_unit_exists` and `install_does_nothing_when_the_package_agent_exists` check these two cases.

Re-install: macOS install boots out a loaded `gui/<uid>/com.timelapserender.trd` before `launchctl bootstrap`, ignoring the failure when nothing is loaded. `reinstall_boots_out_the_loaded_agent_before_bootstrapping` and `reinstall_succeeds_when_nothing_was_loaded` test it.

Windows dry run: `--dry-run` prints the task XML as readable text, before UTF-16 encoding. `dry_run_install_prints_the_readable_task_xml` tests it.

Checks run locally: `cargo fmt --check`, `cargo clippy -p trd --all-targets -- -D warnings`, `bash v3/scripts/check-system-tests.sh` (SYSTEM-TESTS-OK), `bash v3/scripts/check-spdx.sh`, and a `trd service install --dry-run` on macOS whose printed plist equals `macos.plist.golden` byte for byte. The Linux and Windows goldens were checked by applying the same substitutions to their templates. The unit tests run on GitHub through `run_check`.
